多人登录同一网站，共享原始 Excel 模板。支持站点/类目/版本检索、上传新版本、保留旧版、下载原件、完整备份及恢复。纯 Python 3.9+，无需第三方依赖。

## 功能导航

打开后先看到**总览**：今日和近 7 天销售额、订单数、待发货订单、最近提交到店铺的改动，以及常用操作的入口。右上角的 AE / SA 开关对总览、调价与库存、订单、销售与报告、商品查询同时生效。

左侧菜单分三组：

- **上架**：库存识别、填写表格、处理报告。填写表格按五步走：选模板和资料 → 核对字段 → 生成文案 → 检查与导出 → 预检与上架，每次只显示当前一步。
- **运营**：调价与库存、订单、销售与报告、竞品库、商品查询。订单和销售打开页面即自动读取；竞品库独立选择站点，不需要连接店铺。
- **资料**：模板库（页内分页签：全部模板、从规则生成、上传模板、批量生成、叫法归类、与亚马逊对照）、设置（亚马逊连接、店铺、AI、成员、备份）。

较长的使用说明默认折叠在每页的“说明”里。管理员专用页面按角色显示；手机上菜单可横向滑动。页面切换保留当前填写和文件选择，浏览器刷新后需重新选择文件。

升级时停止程序，覆盖新版程序文件并保留 `.data`，重新启动后按 Ctrl+F5 刷新；不需要重新录入店铺、账号或模板。

## 从 SP-API 官方规则生成填写表（1115）

此功能用于 **通过本软件 API 上架**。生成的是本工具按官方字段规则制作的填写表，**不是** Seller Central 原版上传 Excel，不承诺能直接上传到卖家后台的表格入口。

1. 管理员先在「设置 → 亚马逊连接」配置本机凭证。进入「模板库 → 从规则生成」，选择 AE / SA，输入商品名称或类型关键词，按输入文字选择中文/英文搜索。
2. 软件调用官方 Product Type Definitions 搜索接口，显示类型名称和代码；人工选择符合商品实际情况的类型。名称推荐不是自动确认类目，也不证明你的商品事实。
3. 点击「拉取最新规则并生成填写表」。请求当前卖家、当前站点的 `LATEST / LISTING / ENFORCED` 规则，核验下载校验和，记录版本与获取时间。预览字段和复杂规则提示，不自动写模板库或店铺。
4. 可下载三种文件：本工具生成的填写模板、配套商品资料空表（Products 工作表首行为技术表头）、规则快照 JSON。推荐在配套资料空表中填写真实 SKU、标题、品牌、参数等；未知事实保持空白。若把生成模板的 Template 页当作资料来源，技术表头在第 3 行，需在填写页相应调整。
5. 填写真实店铺名称，点「保存并去填写」。软件把预览的同一份模板保存入库并自动选中，无需重新手工上传模板。当前凭证卖家与模板店铺来源冲突时会拒绝保存；不覆盖旧模板。
6. 在填写页上传商品资料，核对字段映射和统一值，完成检查、必要的文案复核，再点亚马逊预检。仅预检通过的 SKU 能继续逐个核对并确认提交；规则检查和预检不等于商品最终已上架，后续状态以亚马逊处理结果为准。

**规则与范围：**条件必填、互斥组合和账户特定约束仍由官方预检最终判断。简单字段展开成可填写列，枚举值提供下拉；无法安全展开的复杂属性保留为 `属性名::json` 高级列，需提供有效的完整属性 JSON，不能把它当作可随意省略的字段。字段不会因为无法展平就静默丢失。SKU 不自动生成，结构性的站点/类型配置不代表补齐了商品事实。

**产物有效期：**未保存的本次产物在内存中保留约 10 分钟，绑定生成成员及当前卖家；过期、重启或切换卖家需重新生成。已保存模板按原有模板库规则长期保留，并随模板备份保存；规则版本更新后可另生成新版本，不覆盖旧文件。文件内不包含 SP-API 密钥、Refresh Token 或可复用的预签名下载地址。

## 以图找同款

左侧菜单“以图找同款”（管理员、编辑者可用）：一次上传最多 10 张自己的商品图（每张不超过 4 MB；宣传图、不同拍摄角度都可以），找出亚马逊上的同款商品和各卖家的价格。图片排成队列，选中一张完成四步后，点击“处理下一张图片”。每一步都由人点按钮开始：

1. **看图出核心词：**已配置的 AI 看图，给出 3–5 个英文核心词。可以先修改再继续。需要能看图的 AI 服务商，即通义千问或 OpenAI。
2. **搜索去重：**用当前店铺的 SP-API 商品目录接口按每个核心词搜索，每个词最多 40 个结果，按 ASIN 合并。同时记下每个商品被哪几个词搜到、最好排在第几。
3. **比图：**AI 把你的图和每个候选的主图逐个比对，给出同款、相似或不同的判断，以及相似度。拍摄角度、背景、宣传文字不算差别。“依据”一栏由程序根据搜索命中、标题和品牌拼出来，每一条都可以核对。
4. **查价格：**对同款、相似和手动勾选的商品（最多 30 个），用 SP-API 查每个卖家的报价，包括含运费的价格、购物车价和卖家数。属于自己已接入店铺的报价会标出店铺名。结果按原图分组，导出的 CSV 含“哪张图”列。

**范围：**全程只用官方接口查询，不修改店铺，也不爬亚马逊网页。尚未保存的图片和会话在内存保留约 30 分钟，只有上传的人能继续查询。点击“保存已搜索图片的结果”可长期保存关键词、候选、比对、价格和查询时间。默认不保存原图；只有明确勾选“我同意保存原图”才会写入原图。已保存记录团队可查看和导出 CSV / Excel / JSON，只有保存者和管理员能删除。历史使用独立的 `.data/lookalike.sqlite3`，模板备份不包含它；请另行导出或停服后备份。没有保存原图的历史可查看和导出，继续比图需重新上传。AI 的判断只是建议，需要人工确认。使用前需要应用有“商品目录”和“定价”相关的角色权限。

## BSR 采集与竞品库

进入「运营 → 竞品库」，支持 AE、SA、US（能否采集取决于该站点实时的 robots 和访问限制）。无需 SP-API 凭证，不登录卖家后台、不读取个人浏览器 Cookie，也不会修改任何店铺商品。

1. 选择站点，填入目标 ASIN 或对应站点的 BSR 类目榜单链接；可补充目标标题、品牌、核心关键词（最多 5 个）和排除词。
2. 确认公开页面访问范围后开始。ASIN 对应多个 BSR 类目时，先选择一个；无法读取商品页时可直接提供类目榜单链接。
3. BSR 每批至多 2 页；默认同时读取每个核心词前 5 页搜索结果（最多 5 个词），合计最多 300 个去重候选。页面显示等待时间估算。搜索页地址仅由程序生成，任何搜索页跳转均停止，请求间隔至少 5 秒，检查 robots 访问限制。遇到验证码、403、429、验证中继页或无法确认的访问限制，会停止并说明原因；不轮换代理、不解验证码、不绕过限制。已取得的部分结果仍可核对。
4. 按 ASIN 去重，查看每个类目的明确排名、来源和采集时间，并记录搜索命中的不同核心词数、命中的词、最好搜索位置（页 / 位 / 广告标记）。可以按核心词命中数排序；来源区分仅 BSR、仅搜索页或两者都有。筛选后手工分为「直接竞品 / 同类不同款 / 替代方案 / 配件耗材 / 同品牌家族 / 无关」，资料不足保留「待核对」，再保存到团队竞品库。
5. 支持 CSV、三工作表 Excel（概览 / 全量候选 / 直接竞品）和完整 JSON 导出。只读成员可以查看、导出已保存批次，不能发起采集或修改分类。

如已有合法保存的 BSR 网页，可通过本地 HTML 导入（≤ 4 MB）进行解析；不会执行脚本或跟随文件中的链接，也不会把导入结果标为实时采集。在线结果同样只代表实际取得的页面，不保证榜单完整覆盖。

**数据含义：**BSR 是对应类目的排名，不是实际销量，也不是关键词搜索位次。不同类目排名分开记录，不直接比较；未知价格、币种留空，不靠位数猜测。标题关键词匹配仅为本地核对提示，不代表真实流量重叠。相同品牌不证明属于同一卖家。页面不自动加载外站缩略图。

**AI 可选：**使用「设置 → AI」中已有服务商，不依赖 Jev。只有另外勾选发送同意并点击分析，才会发送指定目标及候选的文字资料，可能收费，每次请求仍最多 20 个。“给所有未打分的候选打分”会按每批 20 个顺序处理并显示进度；停止按钮会在当前请求返回后停止，失败批次也会停止后续请求。再次点击只处理尚未取得有效分数的商品。1–10 分和分类是待复核的模型建议，不是概率、不保证准确，不会覆盖人工分类；缺少配置不影响采集和手工建库。

**单独备份：**竞品数据放在模板库旁的 `competitors.sqlite3`（默认 `.data/competitors.sqlite3`），不写入模板索引。当前「模板备份」不包含竞品库，恢复模板不会移除它；请单独导出完整 JSON，或停服后复制该数据库妥善保管。未完成任务在重启后标为中断，不自动续爬。

**网络风险：**不使用卖家凭证不等于匿名，亚马逊仍可见公开页面请求的出口 IP。本功能不是防关联工具，也不保证不触发风控。仅在适用条款允许时采集；站点不允许或环境不可访问时，应停止或使用有授权的数据来源。

## 表格类型：上传表格与改价表格

上传原模板和批量生成时均可选择“上传表格”或“改价表格”；默认选择上传表格。类型用于登记、筛选和匹配，原 Excel 内容保持原样。

同一店铺、站点、商品类目和版本号下，两种类型可以各保存一份；同类型中相同内容复用，不同内容仍要求新的版本标签。批量报告和文件名会注明类型。

模板库提供类型筛选，管理员和编辑者可直接在列表中调整已有记录的类型。目标类型已有同店铺、站点、类目和版本时会拒绝调整，保留原记录。只读成员可筛选和下载。

旧库首次打开时自动升级索引，旧记录默认归为上传表格，原文件、ID、店铺和版本保留。旧的改价文件可在模板库手动改为改价表格。完整备份包含类型，新版仍可恢复旧备份，旧备份中缺少类型的记录按上传表格恢复。

库存识别增加“需要的表格类型”，本地匹配和 AI 候选均限定为所选类型；切换类型会清除当前匹配及人工修正，重新识别后下载所选类型的表格。

命令行 `add/list` 同样支持 `--table-type upload` 和 `--table-type price_update`。

## 一份模板支持多个商品类型

新版从原模板可解析的 `ptds` 声明读取多个商品类型，支持清单中的每个类型都参与匹配，保留目标店铺/通用、站点和上传/改价表格类型的限制。模板库可以展开查看清单，也能按支持的中文名称或类型代码搜索、筛选。上传和批量生成预览会展示声明支持的全部类型。

库存中明确提供与声明一致的商品类型代码时可直接匹配；中文别名、品名推断和 AI 判断仍需确认。确认后保留实际商品类别以及对应的声明类型，不会把所有商品都改成模板的登记名称。同一份模板对应多个类别时，下载只保留一份。库存识别页负责匹配和提供表格；填写产品数据请使用独立的“填写表格”页面。

AI 会收到每份候选模板支持的类型，选择有声明的模板时必须返回声明范围内的匹配类型，否则拒绝结果。声明范围不同的旧版本会保留为独立候选；相同范围只向 AI 提供最新版本。`PRODUCT` 等通用名称不会当成覆盖所有商品的通配符。

旧模板的类型索引会在首次读取时从原文件更新，原件字节保持不变。无法解析或部分类型无效会提示核对；每份最多读取 300 个声明类型，超出会提示，不视为全部已覆盖。

## 原表 SKU、商品类目与英文文案（1112.1）

按当前偏好，**SKU 只读取原表，不生成新编号**；保留已有文本 SKU 和前导零。缺少 SKU 时先指定正确来源列或补齐原资料，再生成文案。商品类目先按原表、同义叫法和模板声明类型匹配；无法确定的叫法可生成待核对建议，明确不兼容的类型会拦截。AI 只能在所选店铺、站点模板实际声明的商品类型中选择，不能另造官方类型代码或更换已有的明确类型。

在“填写表格”上传资料并匹配字段后，新商品模式增加文案区域：

1. 默认生成**英文标题、短卖点 / Item Highlight、五点描述**。选择起始商品序号与数量，默认 20 个 SKU，一批最多 100 个；可继续下一批，累计采用到同一份填写结果。模板字段含语言标签时必须与所选语言一致。
2. 使用已有 AI 服务商、区域和模型配置。勾选发送资料及可能产生费用的同意项后，点击生成。只选择本批产品名称、品牌、参数、描述等相关文字；不把价格、库存、卖家记号及账号列作为文案资料发送。此步骤不读取内嵌图片。
3. 候选会显示原表依据，可按 SKU 查看并编辑标题、短卖点、五点和待确认类型。标题最多 75 字符，短卖点及每条五点最多 125 字符；空缺事实不能编造，资料不足可少于五点，并列出需要补充的信息。
4. 核对后可逐个采用或整批采用，再点击“将已采用文案填入并重新检查”。**生成候选不会自动写入模板**；未采用的建议不影响导出。采用只改变所选标题、卖点和确认后的类型，不更改 SKU、品牌、价格、库存等字段。原表文件和模板库原件保留。
5. 相同资料默认复用近期生成内容，缓存仅在服务器内存保存，按成员、模型配置、模板、语言和商品资料区分。缓存不会保存编辑后的人工文案供其他成员使用。首批失败会停止后续调用，已经成功的内容可在重试时复用。

程序会检查结果结构、SKU 是否原样返回、类型范围、原表引用、明显的无依据数字、部分性能/认证声明、重复五点及字符长度；这些检查不能代替逐个商品的事实核对。采用时确认当前 SKU 或本批内容；手动修改后的文字视为用户核对内容。填写检查报告记录采用过的 SKU、文案语言及 `reviewed_copy` 写入依据。五点尚不完整时保留为草稿，不以通用句子凑足。改价／库存模式不提供文案生成，也不接受文案字段覆盖。

## 填写表格（1109.4）

左侧“填写表格”支持 **AE / SA 新商品上传** 和 **已有 SKU 的售价／库存更新**。也可在模板库点击某份模板的“填写”。先选择该店铺、地区和表格类型的原模板，再上传产品资料（CSV / XLSX / XLSM，最大 32 MB，每批最多 1000 行），选择工作表及表头行，读取并匹配字段。页面可下载新商品或改价库存的资料空表，填入真实产品数据后再上传。

字段匹配支持原始技术字段、唯一显示名称和常用品名/参数列名；重复或无法确定的对应关系保持空白，可手动指定来源列，或设置本批统一值。SKU、条码等标识按文字保留，价格和库存按数值检查；Excel 中的 SKU/条码应使用文字格式，避免源文件先丢失前导零。不会从模板已有商品中复制品牌、尺寸、条码、电池或合规声明。已有父子体可按明确的父 SKU、父子关系、颜色/尺码和变体主题列填写与核对；第一版不会凭品名自动生成父体、翻译文案或上传内嵌图片，主图须提供图片链接。

- 新商品模式填写产品资料明确提供的字段，检查可读取的 Data Definitions 必填项和模板下拉规则。条件必填与无法解析的规则列为人工核对项，缺失的产品事实不会编造。单一声明类型可直接使用，多商品类型模板需要明确提供可对应的商品类型。
- 改价／库存模式仅开放 SKU、商品类型、部分更新操作、售价、库存、报价币种及配送渠道等对应字段；不写入标题、品牌、描述及其他商品信息。部分更新使用当前模板允许的实际选项；币种与目标地区核对，不自动换汇。更新库存时如果模板暴露配送渠道字段，必须明确指定，不能从数量推测自配送或 FBA。
- 原模板已有商品数据时，需勾选“在生成副本中替换数据区”。库中原件保持不变；原始工作表、宏、隐藏页、下拉规则、条件格式、列宽及其他 ZIP 部件保留。数据区含公式、合并单元格、旧超链接或嵌入图片等尚不能安全处理的模板会被拒绝，请改用空白原模板。
- 内容一致或互补的重复 SKU 合并，内容冲突的重复 SKU 保留为草稿并提示。每次导出重新核验输入与规则，写入后逐格回读，并比较其他原始部件；核验失败不会交付文件。

下载 ZIP 内含保留原扩展名的填写结果、`待核对问题.csv` 和 `填写检查报告.json`。有错误或待人工确认项时只能生成标明“草稿”的副本；“校验通过后导出”要求本次可检查的规则全部通过，最终能否上传仍以亚马逊处理报告为准。报告包含来源工作表、表头行、字段对应关系、统一值、合并 SKU 的来源行和写入依据；明细较多时最多列出 10000 项问题和 5000 条单元格依据，总数量完整统计，其余可结合字段映射及来源行追溯。

填写操作仅向管理员和编辑者开放，不自动提交亚马逊；普通字段匹配与填写不调用 AI，文案生成需单独同意后使用已配置的 AI。产品资料不存入共享模板库，生成结果供当前用户下载。程序沿用 Python 标准库，无需额外安装 Node 或第三方 Excel 依赖。

## 处理报告回填（1112）

左侧“处理报告”导入卖家后台上传状态页下载的处理报告，支持两种格式：

- **文本报告**（.txt / .tsv）：识别 `original-record-number / sku / error-code / error-type / error-message` 各列和“处理条数 / 成功条数”汇总。
- **Excel 报告**（.xlsx / .xlsm）：读取单元格批注（亚马逊写在出错格上的说明）、填充颜色（橙红为错误、黄色为警告、蓝色为建议）以及汇总表。亚马逊没有公开 Excel 报告的固定格式，程序按常见结构宽松识别；识别不到时会提示，不会编造问题。

选择提交时用的模板后，按模板字段把每条问题对到具体列（例如 “E 列 · Brand Name”）。常见错误代码和提示语翻译成中文分类（必填缺失、取值不被接受、与已有商品冲突、品牌未授权、条码问题、超长、格式等）并给出处理建议，亚马逊原文始终保留在旁边。可按级别、类型筛选和搜索，导出 `处理报告问题清单.csv`。

“填写表格”里正好有同一模板的草稿时，报告页会显示每个 SKU 在产品资料里的行号和该字段的来源列；填写页把被标出的字段标红，可勾选“只看处理报告标出的字段”，改好来源列或统一值后重新检查并生成。报告只在本机解析，不保存、不调用 AI、不向亚马逊提交；查看者也可使用。

## 亚马逊接口：查询、预检与运营（1113）

通过亚马逊 SP-API 直接连接本店铺。除“填写表格”里经确认的上架和“调价与库存”页里经确认的提交外，其余功能都只读取数据，不修改店铺。

- **亚马逊接口**页（所有成员可用）：输入 SKU（一次最多 50 个，可从“填写表格”当前草稿带入），查看是否在售、ASIN、商品类型、售价、自配送可售数量，以及亚马逊标出的问题和中文处理建议；可导出 CSV。
- **填写表格 → 亚马逊预检**（管理员、编辑者）：把本批填写内容按 `VALIDATION_PREVIEW` 模式发给亚马逊校验，亚马逊只返回问题、不保存。一次最多 100 个 SKU，可分批。结果显示在“处理报告”页，出问题的字段在填写页标红。新商品表格按完整商品校验；改价／库存表格按部分更新校验。
- **逐个确认上架**（管理员、编辑者）：新商品表格里预检通过的商品会列在预检区下方，每个 SKU 勾选核对后单独点击“上架”，才会提交到店铺；提交的内容就是预检通过的那一份。预检结果 10 分钟内有效、只能提交一次、只能由发起预检的成员提交。如果店铺里已有同名 SKU，程序不会直接提交，而是提示完整提交会覆盖现有商品（本次没填的字段会被清空），需要再确认一次。亚马逊接受提交后还有自己的处理过程，最终状态请用 SKU 查询核对。
- **模板对照**（“亚马逊接口”页，管理员、编辑者）：选一份库里的模板，对照亚马逊当前对该商品类型的字段定义，列出模板缺少的必填字段和亚马逊已不使用的列。条件必填的字段不在对照范围内。
- **调价与库存**（管理员、编辑者）：每行填写“SKU, 新售价, 新库存”，一次最多 20 行。程序先读取亚马逊上的当前值，再让亚马逊预检；每个 SKU 显示改动前后的数值，勾选核对后单独点击提交，才会修改店铺。预检结果 10 分钟内有效，只能提交一次，且只能由发起预检的成员提交。只改标准售价和自配送库存；促销价、企业价和备货时间保持原样；亚马逊物流商品的库存不能在这里改。提交记录追加保存在数据目录的 `amazon-changes.jsonl`。同页可查看亚马逊物流库存（只读）。
- **订单**（管理员、编辑者）：最近 1–30 天的订单、状态、金额和待发货数量，可查看每单的商品。不读取也不显示买家姓名、地址和联系方式。
- **销售与报告**（管理员、编辑者）：按当地日期统计的每日销售额、订单数和件数；可让亚马逊生成全部商品清单、物流库存、订单明细三种报告，在页面预览并下载 CSV。报告里与买家和收货地址有关的列会被去掉。
- 程序内部只放行这几类请求：查询、带预检标记的校验、生成报告，以及经人工确认的单个商品上架和售价／库存修改；其他请求在发出前就被拦截。没有删除商品、整批一键上架或自动批量改价的功能。预检通过不等于最终生效，以亚马逊处理结果为准。

### 配置凭证（管理员，在运行软件的电脑上操作）

凭证只保存在本机，**不要**发到聊天、截图或共享屏幕里。

1. 在运行软件的那台电脑上，用 `http://127.0.0.1:8765` 打开软件并以管理员登录。
2. 进入“设置 → 亚马逊连接”，填写 Client ID、Client Secret、Refresh Token 和卖家编号（卖家后台“账户信息 → 卖家记号”），点“保存到这台电脑”。
3. 点“测试连接”，应列出 Amazon.ae 和 Amazon.sa。不需要重启软件。

保存后凭证由 **Windows 凭据管理器**加密保管（条目名 `AmazonKing/SP-API`），只有这台电脑上当前的 Windows 账户能读取；页面不会显示已保存的内容，备份和 Git 里也没有。保存和清除只能由管理员在服务器本机操作，其他电脑通过局域网地址访问时会被拒绝。Client Secret 到期轮换后，只填新的 Client Secret、其余留空再保存即可。运行软件的 Windows 账户换了，需要重新填写一次。

备用方式（非 Windows，或不想用页面填写时）：设置环境变量 `SPAPI_CLIENT_ID`、`SPAPI_CLIENT_SECRET`、`SPAPI_REFRESH_TOKEN`、`SPAPI_SELLER_ID`，或把同样四项写进用户目录下的 `.amazon-template-manager/spapi.json`（格式见 [examples/spapi.example.json](examples/spapi.example.json)，可用 `SPAPI_CONFIG` 指定其他位置）。三处同时存在时，环境变量优先，其次是凭据管理器，最后是文件。这些备用方式只适用于主店铺。

**多个自己的店铺：**在“设置 → 亚马逊连接”点“+ 添加店铺”。同一个私有应用最多给 10 个店铺自授权；全部店铺合计最多 25 个。

- **授权：**先登录那个店铺的卖家后台，在“合作伙伴网络 → 开发应用”里给同一个应用点“授权应用”，拿到这个店铺自己的 Refresh Token。
- **填写：**填店铺名称、Refresh Token 和卖家编号。Client ID / Client Secret 留空就沿用主店铺的，主店铺轮换 Secret 后其他店铺自动跟着用新的。如果某个店铺用的是自己单独注册的应用，就填它自己的 Client ID / Secret。
- **存放：**每个店铺的凭证单独存放在凭据管理器里，条目名为 `AmazonKing/SP-API/<店铺编号>`。店铺名称清单存在数据目录旁的 `amazon-stores.json`，这个文件里没有密钥。
- **使用：**页面右上角的“店铺”下拉框决定当前操作哪个店铺，至少接入两个店铺才会显示。在一个店铺做的改价预检、上架预检、报告和生成模板，只能在同一个店铺下提交或下载，切错店铺会被拦下。
- **范围：**目前只支持欧洲区接口，也就是 AE、SA 站点。

**其他主体的店铺（用授权链接接入）：**不同公司主体的店铺不能自授权你的私有应用，改用公开应用（开发者中心里的生产应用，未上架，最多 25 个授权）。

1. 在开发者中心把公开应用的“OAuth 登录 URI”和“OAuth 重定向 URI”都填成 `https://edgerqzh.github.io/amazon-king/authorize.html`（仓库里的 `docs/authorize.html`，只在浏览器里显示亚马逊带回来的授权信息，不发送、不保存任何东西）。
2. 在“设置 → 亚马逊连接 → 用授权链接接入其他主体的店铺 → 公共应用设置”，填应用 ID（`amzn1.sp.solution.…`）、Client ID、Client Secret 和上面那个地址，保存。它们存在凭据管理器的 `AmazonKing/SP-API/public-app` 条目里。
3. 填店铺名称、选站点（AE、SA 属于欧洲区，US 属于北美区；店铺的区域按这里选的站点自动设定），点“生成授权链接”。链接 15 分钟内有效。重新授权已有店铺时，只能选同一区域的站点。
4. 在登录了那个店铺卖家后台的浏览器里打开链接，点同意，会跳到授权结果页；点“复制授权信息”。
5. 回到软件，粘贴到“授权信息”框，点“完成添加”。授权信息 5 分钟内有效、只能用一次。软件用它向亚马逊换取这个店铺的 Refresh Token，存进凭据管理器。

应用还在草稿状态时，链接里带 `version=beta`。已有的店铺也可以在“接入哪个店铺”里选“重新授权”，改成用公开应用。

当前只支持 AE、SA 站点；模板里的卖家记号与凭证不一致时，预检结果会给出提醒。

## 批量商品叫法归类（1106.1）

左侧新增“商品叫法归类”，团队共享保存规则，库存识别时自动读取，无需每次重填或调用 AI。

- **多个叫法归一个类别**：填写标准类别（例如“行李箱”），粘贴“皮箱、旅行硬箱、万向轮旅行箱”，每行一个或用逗号、顿号、分号分隔。
- **多个类别批量导入**：从 Excel 复制“叫法／对应类别”两列，或导入 `.csv`、`.xlsx`、`.xlsm`。每个叫法单元格可写多个叫法；工作簿自动选择可读取的归类表，也可切换工作表。旧式二进制 `.xls` 需另存为 `.xlsx`。
- 点击“检查归类”，查看新增、已存在、内置支持、重复、冲突和无效项；修正后再保存。有冲突或无效项时整批不写入，重复项自动合并。一次最多 5000 个叫法，整个库最多 5000 条自定义规则。
- 已保存规则支持搜索、修改、全选当前筛选、批量删除及导出 CSV。管理员和编辑者可以维护；只读成员可以查看和导出。多个成员同时修改时，过期的预览会被拒绝，刷新重查后再保存。

例如，两列表格可以填写：

```text
叫法                对应类别
皮箱、旅行硬箱      行李箱
美容镜、梳妆镜      化妆镜
```

标准类别应与实际模板或模板声明的商品类型对应，避免把“箱包”等包含多种产品的宽泛名称随意归到单一商品。需要时也能明确登记 Amazon 商品类型代码的中文类别，但不会修改原始工作簿的声明或文件内容。

库存类目列或完整品名命中已保存的自定义叫法，会按对应标准类别匹配；品名/描述只是包含某叫法、出现多个类别，或模板声明范围不兼容时保留待确认。内置叫法仍作为识别建议。匹配继续限定当前店铺/通用模板、地区和上传/改价表格类型。修改规则会使旧 AI 缓存失效，新一轮分析使用最新规则。归类保存在服务器私有数据库，随完整备份导出和恢复；旧备份不包含归类时按空库恢复。

## 简短下载文件名与快捷地区筛选

下载和批量生成的 Excel 文件统一命名为 `表格类型_店铺_地区.xlsx/xlsm`，例如 `上传表格_甲店_AE.xlsm` 或 `改价表格_乙店_SA.xlsx`。保留真实扩展名，不再把商品类目、版本或长哈希拼进文件名。同一下载包遇到相同短名时使用 `_2`、`_3` 等序号防止覆盖。库内原文件名和版本仍保留用于追溯，文件内容保持原样。

模板库增加“AE 阿联酋”“SA 沙特”“全部地区”快捷按钮。点击仅切换地区，保留表格类型、店铺等其他条件，并清空旧勾选；随后可全选当前结果下载。地区依据库内站点记录，不按店铺名称后缀猜测。

## 模板库搜索与删除

支持关键词、表格类型、店铺、地区、商品类别和版本组合筛选，显示匹配数量，并可一键清空筛选。

模板库上方提供“全选当前结果”“取消全选”“下载所选”。可先筛出上传表格或改价表格、店铺和地区，再全选下载；更改筛选条件会清空旧勾选。单份直接下载原始 Excel，多份打包为 ZIP。一次最多 1000 份、原件合计最多 100 MB，超出时可减少勾选后分批下载。

管理员和编辑者可单条删除，也可勾选多条后批量删除。“全选”只选择当前筛选结果；更改搜索条件会清空旧勾选。确认弹窗显示文件、店铺、地区和版本。所有成员均可勾选表格、全选当前筛选结果并下载所选；只读成员不显示删除按钮，接口也拒绝其删除请求。

删除移除所选工作簿和索引，不删除店铺目录、来源绑定或其他版本。批量删除先检查全部 ID，文件移入暂存位置后提交索引删除，提交失败时回滚并还原文件；提交后清理暂存文件，若清理未完成会提示。误删需使用之前的备份恢复；没有回收站。

搜索和删除升级包含后端改动，应停止程序后覆盖新版程序并保留 `.data`，再重新启动，不仅是覆盖 `web`。

## 新功能：库存表识别与缺少模板检查

1. 先把已有亚马逊原始模板上传入库，准确登记站点、类目、版本。
2. 打开“库存表识别”，上传 `.xlsx`、`.xlsm` 或 `.csv` 库存表，选择要上架的目标站点。
3. 选择库存文件后会自动读取表头。通常可直接开始识别，特殊格式可展开“调整工作表与识别列”核对列映射，也可点击“重新读取库存表”。
4. 点击“识别类别并匹配表格”。结果以紧凑列表显示类别，同类商品合并，不展示逐条 SKU 明细。上方固定下载栏支持下载全部或勾选下载；同一模板文件去重，单份直接下载 Excel，多份打包 ZIP。候选模板仍需核对。识别后自动收起输入设置。
5. 库存表有明确类目时，按同站点和同登记类目匹配；仅有品名时，内置常见品类关键词提供建议，不自动判定为确定类目。你可按类别统一确认或修正后重新匹配；未知类别保留待识别提示，不擅自归并。
6. 下载已有模板，或根据补充清单到亚马逊下载缺失的原始类目模板。导出 CSV 仅包含类别、匹配状态和对应模板，不包含逐商品清单。中英文同义类目会合并显示；单次分析最多支持 10000 行商品。

库存文件最大 100 MB，选择后显示实际大小。模板原件、批量转换源文件和备份恢复的上传上限仍为各自原有的 32 MB。库存支持 `.xlsx/.xlsm/.csv`；真正 BIFF 格式的旧 `.xls` 需用 Excel/WPS 另存为 `.xlsx` 并保留图片，不能只改扩展名。仅扩展名误标为 `.xls`、内部实际为 OOXML ZIP 的文件可以直接读取。

库存识别页只检查缺少哪些亚马逊类目模板，不检查价格等商品资料是否齐全，也不自动填表；产品数据填写使用独立的“填写表格”页面。默认使用免费本地规则；可在管理员配置后开启付费 AI 图文识别，只有明确勾选同意后才向所选服务商发送本批商品信息。库存原件不会存入共享模板库，完整分析结果保留在当前浏览器会话；可选的 AI 结果缓存仅在服务进程内存保留 30 分钟并按登录成员隔离，重启即清空；需要留档请导出报告。

## AI 图文识别与本地组合识别

详见 [AI 图文识别使用指南](AI图文识别使用指南.md)。默认推荐通义千问，支持 OpenAI 和 DeepSeek 文字适配器。重复资料合并识别，首批成功后最多 3 批并发，并显示进度和用时；可选择复用最近 30 分钟的相同资料结果，减少重复调用。支持读取标准 Excel Drawing 及可解析 WPS DISPIMG 内嵌图片；不开启 AI 图片分析时，本地规则不读取图片。

本地改进包括中英文类目别名、近似名称候选、独立参数列上下文，以及组合属性推断。例如“三件套 TSA-Compatible Lock 宽拉杆 ABS+PC 20/24/28”可以提出“行李箱”候选，并检索登记为 Luggage/拉杆箱等别名的模板，不能将单独的 TSA 锁判断成行李箱。别名、近似和模型结果仍需确认。

类目名称匹配基于库内登记，不代表亚马逊官方适用性审核；无同名类目也可能只是命名不同。内置品名关键词仅覆盖部分常见品类，不能识别的商品明确标为待确认。先核对库存列和亚马逊实际类目，再决定下载哪个模板。最近入库的版本作为候选，不代表官方最新版本。

更新现有安装：先停止软件并备份整个 `.data`，将新版源码覆盖到原软件目录，保留 `.data` 不动，再用原来的启动方式重启。不要用新建的空数据目录替换旧库。源码包不包含任何公司库存或模板原件。

## 店铺分类与模板内部来源识别

**最省事的方式：上传店铺原模板，填写店铺名称并保存。** 对支持的 AE/SA 模板，软件同时读取并登记完整卖家记号，不需要手抄，也不需要另外导入对照表。已绑定的来源会提示店铺名称。

只有尚无模板的目标店铺，才需要打开“店铺管理 → 手动添加店铺 / 批量粘贴”。这里提供三列可编辑表格，无需输入表头；可以新增行、移出待保存行，或粘贴整表后先预览再保存。支持常见空格分隔及长店名和记号分行复制，存在歧义时拒绝猜测并提示修正。

管理员可在“店铺对照表”粘贴三列表格：`店铺 / 卖家记号阿联酋 / 卖家记号沙特`。支持 Excel 复制的制表符文本、CSV、分号分隔、Markdown 表格，以及聊天中的空格对齐和单元格换行。可带表头，也可不带表头；无表头时固定按 `店铺 / AE / SA` 顺序识别。缺少某地区时，Excel/CSV 保留空单元格，或明确填写 `-` / `—`；无法确认地区或有行缺失记号时整批拒绝，避免跨行拼错。支持去除单元格中的 `<br>` 和开头的 BOM。识别预览不写入数据库，核对三列后再点击保存。同店铺 AE/SA 记号可以不同。为了批量生成，完整卖家记号保存在服务器私有数据库及完整备份中，不写入公开软件包；请保护数据目录和备份。导入后，即使该店铺尚未存模板，也会出现在店铺选项中。冲突时整批不保存，不覆盖既有归属。

真实对照表需要在你自己部署的软件中导入，公共下载包不包含实际店铺名称或卖家记号。完整备份包含导入的目录和来源绑定，即使目录尚未关联模板也可恢复。

上传与库存分析均选择店铺。同站点、同类目、同版本可在不同店铺分别保存，不相互覆盖。匹配仅限目标店铺及允许共享的“通用模板”，本店专用模板优先；不借用其他店铺专用模板。

新版读取 Amazon `Template!A1` 设置中的 `contributorId`，识别时使用其摘要和尾号提示。第一次需要你绑定到真实店铺名称或导入对照表；以后同一标识的模板即使改名，也能提示已绑定店铺，错店保存会被拒绝。缺少可用标识时仍需手动确认，不用文件名、品牌名或 AI 猜账户归属。这是文件来源线索，不是登录认证或卖家账户所有权验证。

“设置店铺”及导入对照表只更改目录归属，不会修改原始工作簿。需要修改记号时，使用独立的“同地区多店铺模板生成”功能，生成副本并保留修改记录；不能把本地检查通过当成亚马逊处理成功。

## 上传一次，生成同地区多店铺模板

1. 上传已有店铺原模板即可自动登记完整记号。旧版本只有摘要时，可重新上传对应原模板复用旧记录，或在店铺管理中直接填写/粘贴整表；摘要无法反推完整记号。
2. 在“同地区 · 多店铺模板生成”选择一份 `.xlsm` 或 `.xlsx`。软件从内部主站点识别地区，AE 只列 AE 记录，SA 只列 SA 记录，不依据店铺名称后缀判断，也不提供跨地区改造。
3. 选择本批的表格类型（上传表格或改价表格）。默认勾选同地区全部店铺（含已登记的来源店铺，来源相同则保留原件内容）；可调整目标名单、类目和批量版本。页面显示已选店铺数量，支持全选和清空选择，无需逐个店铺再次上传。
4. 选择生成方式：默认“仅保存到模板库”，不自动下载；也可选“保存并下载 ZIP”或“仅下载 ZIP”。仅保存时不打包 ZIP，完成后显示逐店入库结果，可手动下载本批已入库模板、导出生成报告，或直接查看模板库。仅下载不增加模板库记录。
5. 默认开启“自动编号”，使用北京时间当天的标签，例如 `2026-11-09-批量`。同一天继续生成会自动递增为 `2026-11-09-批量-02`、`-03`，按所选店铺、表格类型、站点和类目检查已有编号，无需手动改日期或版本。多人同时生成时由服务器确认未使用的编号，结果区与 ZIP 报告显示实际版本。
6. 取消“自动编号”可手动填写版本。手动模式下，相同店铺/表格类型/站点/类目/版本已有不同内容时仍会拒绝整批入库；相同文件可复用，原版本不会覆盖。自动模式中若本批部分店铺入库失败，保持相同源文件、目标名单和类目重试，会沿用本批实际版本并复用成功项；全部成功后自动准备下一个版本。

生成仅替换 `Template!A1` 的主 `contributorId`，保留其他元数据（包括来源偏好设置）、字段、站点、预填商品、样式、验证、图片和 VBA 内容。不修改源文件，不重建工作簿；读取生成文件确认目标标识，并检查计划外 ZIP 部件未变化。文档数字签名文件不处理。

一次最多 50 店，生成的工作簿合计最多 100 MB。个别入库因磁盘等运行故障失败时会明确显示；选择下载的模式会在 ZIP 保留副本，仅保存模式则显示逐店失败原因，可检查磁盘后用相同源文件和版本重试，成功项会复用。源表有商品数据时也会复制到各店，使用前请核对。

该功能基于用户已实测成功的主标识替换方式提供，不保证所有模板和店铺均能通过亚马逊审核；请以各店铺处理报告为准。批量生成不调用 AI、不收取模型调用费用，也不会自动向亚马逊提交。

含来源账户标识的模板不能标为通用模板。旧数据升级时保留原件，旧店铺未知的账户模板显示“需绑定店铺”，绑定前不参与通用匹配。通过“设置店铺”更正同一来源归属时，会原子地调整同账户来源的全部已存模板，冲突时全部保持不变。普通无账户来源模板只调整选中项。

会显示模板内部主站点、商品类型、字段数量、数据起始行和预填内容提醒，不会清空或重建原件。相同商品类型不代表不同店铺模板可以互换，也不能用固定列号填不同文件。

店铺分类不改变账号权限：当前团队成员仍可查看所有店铺，分类用于组织与避免误选，不是店铺之间的访问隔离。

## 多人共享部署

所有人必须连接同一台长期在线的电脑或服务器。各自运行一份软件会创建独立模板库，不会自动共享。

局域网示例，假设运行电脑的内网地址为 `192.168.1.10`：

```sh
python app.py --host 0.0.0.0 --allowed-host 192.168.1.10:8765
```

在可信局域网访问该地址，并在操作系统防火墙仅放行可信网段。HTTP 不加密；互联网部署须使用 HTTPS 反向代理，后端只绑定回环地址：

```sh
python app.py --host 127.0.0.1 --allowed-host templates.example.com --https --data-dir /srv/template-manager/data/library
```

例如 Caddy 配置（域名解析到服务器，安装 Caddy 并开放 80/443）：

```caddyfile
templates.example.com {
    reverse_proxy 127.0.0.1:8765 {
        header_up Host {host}
    }
}
```

将软件作为受系统进程管理器监管的单个实例运行；不要在不同进程、不同磁盘同时运行多个写入实例。当前采用单进程串行写入，适用于小团队文件共享。

## 权限与数据

“完整备份”包含原件、模板索引及店铺归属，恢复时从原件重建来源绑定，不含登录账号密码和 AI 密钥；恢复仅允许空模板库，账号保持独立。备份上传最大 32 MB，展开最大 512 MB；超过此规模时停服复制整个 `.data` 目录。迁移账号需停服备份整个数据父目录，并安全保存。不要将 `.data` 提交到公共仓库。

模板库保存和共享原件；“填写表格”页面从产品资料生成填写副本，支持新商品、改价库存及经确认的 AI 文案。此软件不提供多人同时编辑同一份 Excel 单元格的能力，也不直接提交亚马逊。

当前账号管理支持新增；停用/改密尚无图形界面。管理员如需紧急撤销成员访问，可停服后通过受控 SQLite 管理操作移除该账号和会话；此版本适合受信任小团队试用，不宜作为大规模公共网盘。

## 库存识别界面

库存页分为上传库存、识别类别、获取对应表格三个阶段。AI 图片及费用参数、列映射、识别说明均可展开；识别完成后显示紧凑的类别模板列表，模板缺失和类别待确认分别标注。桌面和手机均为每类一行，长文件名可悬停查看。

完成后无需刷新：点击页面上方“上传新库存”或固定下载栏中的“识别下一份库存”，直接选择新文件。新文件自动读取表头，保留目标店铺、站点和 AI 选项，清空上一份的结果、列映射和人工修正；每份文件的 AI 发送确认需重新勾选。取消文件选择会保留当前结果，重新选择同一文件也能再次读取。结果区显示本次库存文件名，避免混淆。

库存识别的目标店铺需显式选择，下拉框显示该店铺在所选地区的模板数量，不再默认选中“通用模板”。“通用模板”仅检索公共库，不会借用其他店铺的专用文件。如果结果为零，先核对店铺和地区；未匹配到文件的类别行显示“暂无文件”，不能把已识别类别当成已取得模板。

识别后，三步流程下方出现固定的“下载全部”和“下载所选”按钮，以及“全选可下载表格”和“取消全选”选项：匹配一份时直接下载原始 Excel，多份时按文件 ID 去重并打包 ZIP。类别列表仍能分别下载，候选类别保留待确认提示。零匹配时主按钮禁用并说明需要检查店铺、地区和模板库。只读成员也能下载其已有读取权限的模板。

右上角界面标识为“多类型匹配版 1105.1”。本版包含多商品类型匹配、类型索引更新和短下载名的后端调整。升级前停止程序并备份 `.data`，保留原 `.data` 并覆盖完整程序，重启后 Ctrl+F5 刷新。旧输入框与新脚本混用时会自动升级为下拉框；若当前数据目录没有店铺记录，会明确提示先登记，不会凭空生成店铺。

千问调用失败时可在 AI 设置选择与密钥匹配的服务区域，保存后点击“测试模型连接（少量计费）”。新版会显示脱敏后的具体服务商错误码，不把单独的 HTTP 404 当成确定根因。库存数字表头会提示核对实际表头行。
